# Section 1 - 2. Next.js 사전 렌더링 이해하기

## 1. 사전 렌더링

Next.js의 사전 렌더링은 **서버에서 HTML을 먼저 만들어 브라우저에 전달하는 방식**이다.

```text
브라우저 요청
↓
서버에서 React 렌더링
↓
HTML 생성
↓
브라우저에 전달
↓
화면 표시
```

React의 일반적인 CSR 방식보다 초기 콘텐츠를 빠르게 보여주는 데 도움이 된다.

### a. CSR

CSR(Client Side Rendering)은 브라우저에서 JavaScript를 실행해 화면을 만든다.

```text
HTML + JavaScript 다운로드
↓
브라우저에서 JavaScript 실행
↓
화면 생성
```

JavaScript를 다운로드하고 실행해야 하므로 초기 화면 표시가 늦어질 수 있다.

### b. 차이

```text
CSR
→ 브라우저에서 화면 생성

사전 렌더링
→ 서버에서 HTML을 먼저 생성
```

핵심은 **초기 HTML을 어디에서 만드는가**이다.

---

## 2. FCP와 Hydration

### a. FCP

`FCP(First Contentful Paint)`는 **사용자가 화면에서 첫 번째 콘텐츠를 확인할 수 있게 되는 시점**이다.

사전 렌더링된 HTML을 먼저 전달하면 초기 콘텐츠를 빠르게 표시하는 데 도움이 된다.

### b. Hydration

서버에서 받은 HTML은 먼저 화면에 표시될 수 있지만 React의 이벤트와 상호작용 기능은 아직 연결되지 않은 상태일 수 있다.

브라우저에서 JavaScript가 실행되면서 기존 HTML에 React 기능을 연결하는 과정을 **Hydration**이라고 한다.

```text
서버 HTML
↓
화면 표시
↓
JavaScript 실행
↓
React 기능 연결
↓
Hydration
```

---

## 3. TTI와 전체 흐름

`TTI(Time To Interact)`는 **사용자가 페이지와 실제로 상호작용할 수 있게 되는 시점**이다.

```text
브라우저 요청
↓
서버에서 HTML 생성
↓
화면 표시
↓
FCP
↓
JavaScript 실행
↓
Hydration
↓
상호작용 가능
↓
TTI
```

정리하면:

```text
FCP
→ 콘텐츠가 보이는 시점

Hydration
→ HTML에 React 기능을 연결하는 과정

TTI
→ 실제 상호작용이 가능해지는 시점
```

---

## 4. 핵심 정리

* Next.js는 서버에서 HTML을 먼저 만들어 전달하는 사전 렌더링을 사용한다.
* CSR은 브라우저에서 JavaScript를 실행한 뒤 화면을 만든다.
* 사전 렌더링은 초기 콘텐츠 표시 속도를 개선하는 데 도움이 된다.
* `FCP`는 첫 콘텐츠가 화면에 보이는 시점이다.
* `Hydration`은 서버에서 만든 HTML에 React의 상호작용 기능을 연결하는 과정이다.
* `TTI`는 사용자가 실제로 페이지와 상호작용할 수 있게 되는 시점이다.
* 핵심 흐름은 **`서버에서 HTML 생성 → FCP → Hydration → 상호작용 가능`**이다.
